# Releasing

Push a version tag to create a draft GitHub Release. Review the generated notes,
then publish the release to start PyPI publication. GitHub Releases also serves
as the project changelog.

## Required Local Checks

From a prepared development checkout, run validation and build before tagging:

```bash
npm --prefix tests/typescript ci
npm --prefix editors/vscode ci
pdm run validate
pdm run smoke:cli
pdm build
pdm run package-check
npm --prefix editors/vscode test
npm --prefix editors/vscode run package
pdm run pytest tests/offline/tooling/test_language_server.py
```

`pdm run validate` runs Ruff, strict mypy, docs-check, the offline Python tests,
and editor tests. Live OpenAI tests remain opt-in and are not part of the release gate
unless the release changes live adapter behavior.

## Process

1. Choose the next semantic version tag.
2. Replace `vX.Y.Z` with that tag, then create and push it:

```bash
git tag vX.Y.Z
git push origin vX.Y.Z
```

3. Wait for the `Create Draft Release` workflow to complete.
4. Review the drafted GitHub Release generated by
   `btfranklin/release-notes-scribe`.
5. Confirm the draft release includes
   `contract4agents-vscode-X.Y.Z.vsix` as a release asset.
6. Publish the GitHub Release.
7. Confirm the `Upload Python Package` workflow completes.
8. Download the published VSIX into temporary VS Code state, install it, and
   confirm the reported extension version matches the release tag:

```bash
tmpdir="$(mktemp -d)"
gh release download vX.Y.Z --repo btfranklin/contract4agents \
  --pattern "contract4agents-vscode-X.Y.Z.vsix" --dir "$tmpdir"
code --user-data-dir "$tmpdir/user-data" \
  --extensions-dir "$tmpdir/extensions" \
  --install-extension "$tmpdir/contract4agents-vscode-X.Y.Z.vsix" --force
code --user-data-dir "$tmpdir/user-data" \
  --extensions-dir "$tmpdir/extensions" \
  --list-extensions --show-versions
```

## Workflow Boundaries

- `.github/workflows/python-package.yml` validates pushes and pull requests
  across supported Python versions.
- `.github/workflows/vscode-extension.yml` tests the real Python language-server
  boundary and builds the VS Code VSIX on pushes and pull requests.
- `.github/workflows/create-draft-release.yml` runs on pushed `v*.*.*` tags and
  gates the exact tag with Python validation, CLI smoke tests, package checks,
  and editor tests. It then drafts release notes with
  `btfranklin/release-notes-scribe` and attaches the version-matched VSIX.
- `.github/workflows/python-publish.yml` runs when a GitHub Release is
  published. It checks out the release tag, repeats the Python behavior and
  package gates, and then publishes to PyPI through trusted publishing.
- Versioning is SCM-derived through the PDM configuration in `pyproject.toml`.

Do not publish the GitHub Release before the tag-triggered release-notes workflow
has populated the draft. The PyPI publishing workflow does not generate release
notes.
